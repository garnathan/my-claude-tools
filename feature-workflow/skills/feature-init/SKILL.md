# feature-init — set up feature tracking for a project

One-time setup. Creates the `docs/features/` tree, writes `.feature-workflow.yml`, and gitignores the auto-generated `DASHBOARD.md`. No CI, no API keys — the default reviewer is a local Claude subagent.

The shipped script is at `scripts/init.py` *in this skill's directory*.

## Step 1 — Check for existing setup

Read `.feature-workflow.yml` in the project root. If it exists, show the current config (branch prefix/target, review mode/provider) and ask whether to change settings or stop.

## Step 2 — Gather configuration

`$ARGUMENTS` may carry `<branch-prefix> <target-branch>`. Otherwise ask (defaults in **bold**):

1. **Branch prefix** — `feature/` · `feat/` · `fix/` · `topic/` (default **`feature/`**).
2. **Target branch** — what feature PRs merge into: `dev` · `develop` · `main` · `staging` (default **`dev`**).
3. **Review mode** — WHO reviews (default **`internal`**):
   - `internal` — a local Claude subagent runs the review prompt and posts the verdict. No CI, no keys. Works anywhere.
   - `external` — an external CI bot reviews. A documented extension (see [../shared/review-channel.md](../shared/review-channel.md)); until wired, it falls back to a local review.
   - `skip` — no review by default (you can still override per-feature).
4. **Review provider** — WHERE PRs + comments live (default **`github`**): `github` · `bitbucket` · `none` (no PR; reviews recorded only in the feature's `reviews/` side-channel and `/feature-ship` merges locally).

## Step 3 — Run the init script

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/feature-init/scripts/init.py" . \
  --prefix "<prefix>" --target "<target>" \
  --review-mode "<internal|external|skip>" --provider "<github|bitbucket|none>"
```

It creates `docs/features/` + initial `DASHBOARD.md`, writes `.feature-workflow.yml`, and adds `DASHBOARD.md` to `.gitignore` (untracking it if needed — it's regenerated by the hook). `--update` re-syncs only the `.gitignore` entry.

## Step 4 — Confirm

```
## Feature Workflow Initialized
Config: .feature-workflow.yml
  Branch prefix:   <prefix>      Target: <target>
  Review mode:     <mode>        Provider: <provider>
Branches: <prefix><feature-id>  →  <target>

Next: /feature-capture to create your first feature.
```

If the user chose `external`, remind them no CI reviewer is wired yet (it falls back to local review until they follow [../shared/review-channel.md](../shared/review-channel.md)).

## Notes

- The plugin's hooks (DASHBOARD regeneration on feature-file writes; block direct edits to DASHBOARD.md) are wired at the plugin level — no per-project install step.
- To change settings later, edit `.feature-workflow.yml` directly or re-run `/feature-init`.
